# Repurposer

Work drifts. An AI asked "is there an opening for eBay Live in this community?" ends up perfecting a creator-concentration count, re-labelling 40 rows, or debating a decimal place. Each step looked reasonable; the sum no longer answers the question. Feedback drifts the same way: a reviewer lists twelve correct micro-fixes and only mentions at the end that the whole thing is aimed at the wrong target. By then the reader has already started fixing the twelve things.

This skill repurposes the work back onto the main lens. The order is the point: **context first, then item by item, every item tied back to the main question.** Never the reverse.

## Step 1: Find the main lens

Before reading the work in detail, write down what the user is actually trying to learn or decide, as one to three plain questions. Take them from the user's own words in this conversation, a brief, a handoff document, or the research checkpoint. If the user stated them earlier, reuse their wording rather than inventing new questions.

Example (eBay Live community research):
- Q1. Is live buying already happening in this community, and on which platform?
- Q2. Who drives it: creators, sellers, partners?
- Q3. Is there an opening for eBay Live, or is eBay pushing into empty space?

If the lens is genuinely unclear and nothing in context settles it, state your best reading of it in one line and proceed. Do not stall the feedback on it.

## Step 2: Read the work through the lens

For each part of the work (slide, section, chart, claim, function), ask:
- Which main question does this help answer? If none, it is a candidate to cut or demote.
- What is its "so what" for that question? If the work does not say, that is the gap to name.
- Is it drift? Signs of drift:
  - precision that would not change the answer (counting to the exact row when "most" or "a handful" leads to the same decision);
  - process, methodology or caveats taking more space than findings;
  - a side topic explored because data was available, not because it bears on the question;
  - polishing labels, formatting or wording while the core answer is still missing;
  - answering an adjacent question (what is popular) instead of the asked one (is there an opening for us).

Keep real caveats, such as a sample that cannot support the claim or a provenance problem, but put them under the "so what" they qualify, not ahead of it.

## Step 3: Write the feedback in this order

Use this structure. The first block must make sense on its own, because it is what changes the direction of the work.

```
CONTEXT FIRST
- The main question(s): Q1 / Q2 / Q3 in plain words.
- Where the work is aimed now vs where it should be aimed (one or two sentences, direct:
  "this is aimed at X; the question is Y").
- What to change globally so every part points at the questions (2–4 bullets at most).

ITEM BY ITEM (slide by slide / section by section, in the work's own order)
[Item name]
- Serves: Q1 / Q2 / Q3 / none
- So what: the one-line takeaway it should give for that question
- Fix: the reframe or missing piece that makes it answer the question
  (or "Cut it" / "Move to appendix", with the reason)
- Test (optional): the one check that would confirm or kill the claim

CLOSE
- Answers so far: for each main question, what the work currently lets us say
  (answered / partly / not yet) and the single next step that would move it most.
```

Why this order: the reader acts on what comes first. If the opening is "change the title on slide 3", they fix titles. If the opening is "this deck answers what's popular; we need whether there's an opening for eBay", they rethink the deck, and the item-by-item notes become instructions for doing that rethink.

## Calibration

- Be direct about misdirection. "I think this is aimed at the wrong target" is more useful than a gentle hint buried in item 7.
- Credit what already serves the lens, and say which item is strongest. That tells the author what to build around.
- Keep micro-fixes (typos, labels, decimals) out unless they change a conclusion. If a few matter, put them in a single short "small fixes" line at the end of an item, not as items of their own.
- Match length to the work: a 4-slide deck gets 4 short item blocks, not 4 essays.
- If the user asks for something pasteable to another AI, write the whole thing addressed to that AI ("You…"), ready to copy, with no meta-commentary around it.

## Applying it to your own work

When a long task of your own starts producing counts, re-labels and caveats, stop and run Step 1 on yourself: restate the main questions, check which current activity moves an answer, and drop or defer what does not. Report to the user in the same order: where the answer stands against each question first, details after.
